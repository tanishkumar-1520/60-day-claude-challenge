# Key Learnings — Day 50

1. **Defending is different from presenting.** A strong resume statement still needs evidence, ownership, context, and a clear explanation of how the outcome was achieved.
2. **Adaptive questioning creates realistic practice.** Follow-up questions should react to the user's previous answer instead of repeating a fixed interview script.
3. **Evidence is central.** Metrics, artifacts, feedback, screenshots, before/after comparisons, and concrete outcomes make experience claims easier to defend.
4. **Ownership needs precision.** Candidates should distinguish their individual contribution from what the wider team accomplished.
5. **Trade-offs reveal depth.** Explaining alternatives, constraints, decisions, and lessons makes an experience story more credible and specific.
6. **Progress indicators improve practice loops.** Evidence, specificity, and confidence scores make weaknesses visible and encourage another practice round.
7. **Graceful fallback matters.** The application remains usable with deterministic questioning when an API request is unavailable.
8. **Single-file architecture is useful for learning.** HTML, CSS, and JavaScript in one file makes the project easy to run locally, inspect, and commit to GitHub.
9. **Privacy-aware design matters.** The local prototype keeps session data in browser localStorage and avoids requesting an API key from the user.
10. **The final report should be actionable.** It should identify concrete next steps rather than merely assigning a score.
