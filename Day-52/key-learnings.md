# Day 52 — Key Learnings

1. A clear architecture reduces implementation uncertainty.
2. Database design should be validated against user stories rather than designed independently.
3. API contracts should be defined before implementation.
4. Every UI screen should have a specific user purpose.
5. Separating frontend, backend, database, integrations, tests, and documentation makes the project easier to maintain.
6. AI should be called from the server so API credentials are not exposed in the browser.
7. Keeping v1 scope focused makes the remaining implementation timeline more realistic.
