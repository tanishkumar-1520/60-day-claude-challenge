# Day 37 — Task Compass 🧭

## Project

**Task Compass — Hospital / Healthcare Organizational Thinking Simulation**

## Objective

The goal of Day 37 was to build an interactive educational game that teaches how work flows through a real organization.

Instead of testing job titles, Task Compass focuses on:

* Ownership
* Delegation
* Collaboration
* Escalation
* Workflow thinking
* Communication between different roles

## Workplace Type

**Hospital / Healthcare**

The simulation uses realistic healthcare workplace situations involving roles such as:

* Attending Physician
* Nurse / Charge Nurse
* Patient Support
* Quality & Safety
* Health IT
* Operations Manager
* Pharmacist
* Laboratory Team

## Three Stages

### Stage 1 — Who Owns This?

Players receive realistic healthcare work situations and identify the most appropriate primary owner.

The player can drag a role card into the ownership slot.

After submission, the application explains:

* Primary Owner
* Why they own the task
* Which roles may assist

The stage contains **3 scenarios**.

### Stage 2 — Task Routing

Players manage incoming work by building a workflow.

They drag different healthcare roles into the correct sequence.

After submission, the application explains:

* The commonly used workflow
* Why the order makes sense
* How work moves between teams

The stage contains **3 scenarios**.

### Stage 3 — Collaboration Challenge

Players handle larger organizational situations where one person cannot reasonably solve everything alone.

They can assign up to four roles:

* Primary Owner
* Supporting Teams

The application then displays:

* Primary Owner
* Supporting Teams
* Reasoning
* Possible Communication Flow

The stage contains **3 scenarios**.

## Organizational Thinking Dashboard

At the end of the simulation, Task Compass generates a learning dashboard based on four areas:

1. **Ownership**
2. **Delegation**
3. **Collaboration**
4. **Workflow Thinking**

The dashboard uses visual progress bars instead of treating the experience as a traditional exam score.

## Final Reflection

The application provides reflection around:

* What was understood well
* Where responsibility may have been over-assigned
* Where collaboration may have been underestimated
* One insight about how organizations actually work

### Key Insight

> Work often moves through a network rather than a straight line.

A primary owner may coordinate an outcome while other teams contribute expertise, evidence, approvals, clinical knowledge, technology support, or operational resources.

## Technologies Used

* HTML5
* CSS3
* Vanilla JavaScript

## Technical Requirements

The application was designed as a **single self-contained HTML file**.

It does not require:

* React
* Tailwind CSS
* npm
* Babel
* External libraries
* External APIs
* Internet connection

All scenarios are stored as JavaScript objects and the interface is generated dynamically using reusable JavaScript functions.

## Learning Outcome

This project helped demonstrate that organizational problems are rarely solved by simply identifying one person with the right job title.

Effective work often requires:

* Clear ownership
* Appropriate delegation
* Cross-team collaboration
* Logical workflow design
* Communication and escalation
* Understanding how responsibilities connect
